# Privacy/burn deployment and acceptance

This PR is ready for code review/merge after its repository tests pass. **Merge is not production deployment or a security sign-off.** The connected Supabase account could not access the production project, so these steps were not executed here.

## Rollout

1. Merge the PR and sync Bolt to the merged main.
2. Apply both migrations in order and confirm success:
   - `20261003120043_harden_privacy_boundaries.sql`
   - `20261003122647_durable_content_burns.sql`
   The second migration enables hosted `pg_cron`, `pg_net`, and Supabase Vault, creates private cleanup tables and a random worker token, and schedules expiry/cleanup/orphan jobs. It does not SQL-delete Storage metadata. Scheduled expiry/orphan processing **will remove already-expired/tombstoned content and aged unreferenced files** once active. Review live path/reference formats first, especially legacy media.
3. In the production SQL editor, configure the public project URL in Vault. This is a URL, not a service key. The worker's secret token was generated by the migration and must not be copied into app code or logs:

   ```sql
   DO $$ BEGIN
     IF NOT EXISTS(SELECT 1 FROM vault.decrypted_secrets WHERE name='wmu_burn_project_url') THEN
       PERFORM vault.create_secret('https://vdhrcbaggplcktjamwcj.supabase.co','wmu_burn_project_url');
     END IF;
   END $$;
   ```

4. Deploy all six Edge Functions from this revision (CLI supports multiple names):

   ```sh
   npx supabase functions deploy copy-to-vault notify-screenshot burn-content process-content-burns disconnect-couple delete-account --project-ref vdhrcbaggplcktjamwcj --use-api
   ```

   `supabase/config.toml` keeps JWT verification on the user functions and turns it off **only** for `process-content-burns`. The worker independently verifies its dedicated Vault token. Do not deploy all six with a global `--no-verify-jwt` override.
5. Confirm all three cron jobs are active and the worker responds successfully; then publish the app update through the normal EAS/OTA workflow. New private avatar resolution requires this app update. Older installed app UIs can still incorrectly imply immediate completion, although their deletes are captured by the database triggers.

## Content-free operational checks

Run `supabase/tests/privacy_live_verification.sql` for policies, ACLs, bucket privacy and reviewer membership. Also:

```sql
SELECT jobname,schedule,active FROM cron.job WHERE jobname LIKE 'wmu-burn-%';
SELECT state,count(*),min(created_at) AS oldest FROM public.content_burn_jobs GROUP BY state;
SELECT count(*) AS pending_accounts FROM public.account_burn_requests;
SELECT count(*) AS expired_copy_leases FROM public.media_copy_leases WHERE expires_at<=now();
SELECT count(*) AS overdue_chat FROM public.chat_messages WHERE burns_at<=now();
SELECT count(*) AS overdue_vault FROM public.vault_items WHERE expires_at<=now();
SELECT id,public FROM storage.buckets WHERE id IN('chat_media','vault','avatars');
```

Avoid displaying Vault secrets or private message/media fields. Investigate old pending jobs; retry backoff is bounded at one hour and a 10-minute abandoned-copy lease can delay completion. Completion does not rely on either app staying open.

## Acceptance on disposable test data

- Use two unrelated couples plus the actual Apple reviewer pair. For each user JWT, attempt foreign table reads/writes, screenshot IDs, main/thumbnail copies, Storage list/download/sign/remove, forged relationship/activity inserts and direct privileged RPCs. Foreign private data must remain inaccessible.
- Burn a message with two Vault saves, video/photo thumbnails and activity references. Verify all linked rows are absent, all Storage API paths are gone, manifests are cleared, and both current app screens/viewers refresh. Repeat from the non-uploader partner.
- Delete wishes with original and completion images. Burn each page and Burn It All. Verify accurate points reset and intended preservation of weekly streaks/first-moment milestone for category burns.
- Stop both apps; let timers expire. Verify database and physical cleanup runs from cron. Healthy scheduler processing has latency; do not promise exact-clock erasure from cached views.
- Inject a Storage failure: content becomes unavailable in the live app, the job remains pending, the UI does not claim completion, and the worker eventually finishes after recovery. Repeat a burn after its database row is gone; it must still include outstanding files.
- Start a Vault copy concurrently with a burn. The reserved destination must be included; completion must wait for the lease/copy to finish or safely expire, and later cleanup must not resurrect a usable copy.
- Delete a test account, including a reviewer account: verify all relationship/avatar inventories are captured before auth deletion, entitlement FK no longer blocks removal, outages leave a locked pending request, and auth removal occurs after confirmed file cleanup. Test stale access/refresh tokens too.
- On iOS and Android, check image/video/picker/upload caches, app background snapshots, device-backup exclusions, and offline partner behavior. Verify managed cleanup on sign-out and account switches.

## Before advertising “gone forever”

Record actual database/PITR retention and expiry, separate exports and CDN/browser eviction bounds. Prove an old-backup restore does not restore burned text; the restore-time deletion registry must survive independently of that old backup. Native cached/exported originals and screenshots are outside server deletion control. This PR does not provide end-to-end encryption or cryptographic erasure of historic backups.
